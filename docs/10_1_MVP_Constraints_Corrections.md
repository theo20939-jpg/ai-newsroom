# 1. Назначение документа

Этот документ является дополнением к основной технической документации.

Он определяет границы MVP-разработки.

Главная задача:

не допустить преждевременного усложнения системы.

---

# 2. Главный принцип MVP

AI Newsroom MVP должен быть:

- рабочим;
- стабильным;
- дешёвым в эксплуатации;
- простым для поддержки.

---

Главный приоритет:

> Получить работающего AI SMM-помощника, который каждый день приносит качественные новости и помогает создавать контент.
> 

---

# 3. MVP Architecture

Первая версия строится как модульное приложение.

Не использовать микросервисы.

---

Архитектура:

```
Telegram Users

↓

Telegram Bot

↓

FastAPI Backend

↓

Core Application

├── News Collector

├── Workflow Manager

├── AI Capabilities

├── Database

└── Notification System
```

# 5. Что входит в MVP

## 5.1 Сбор новостей

Источник:

- выбранные Telegram-каналы;
- RSS источники.

---

Система должна:

- получать новости;
- сохранять их;
- удалять дубликаты;
- классифицировать.

---

# 5.2 Анализ новостей

AI анализирует:

- важность;
- соответствие аудитории;
- потенциальный интерес;
- актуальность.

---

# 5.3 Оценка новости

Каждая новость получает:

```
Final Score 0-100
```

На основе:

- важности;
- вовлечённости;
- авторитета источника;
- свежести.

---

# 5.4 Telegram Digest

Бот отправляет подборку:

Пример:

```
🔥 Главные новости дня

1. OpenAI выпустила новую модель

Почему важно:

...

Оценка:

92/100
```

---

# 5.5 Генерация контента

AI создаёт:

- варианты постов;
- заголовки;
- описания.

---

# 5.6 Проверка качества

Перед отправкой:

AI проверяет:

- факты;
- стиль;
- ошибки.

---

# 5.7 Human Approval

Финальное решение всегда принимает человек.

Схема:

```
AI подготовил

↓

SMM команда проверила

↓

Публикация
```

---

# 6. Что НЕ входит в MVP

Следующие функции откладываются.

---

## Генерация мемов

Причина:

требует отдельной системы:

- трендовый анализ;
- визуальная генерация;
- проверка оригинальности.

---

## Автоматическая публикация

Пока только подготовка контента.

---

## Полноценное обучение AI

Нет автоматического изменения поведения модели.

---

## Сложная Vector Memory

В MVP использовать:

PostgreSQL.

---

## Микросервисная архитектура

Не использовать.

---

## Celery

Не использовать.

При необходимости добавить позже.

---

# 7. AI Architecture Rules

AI работает через:

```
LLM Gateway
```

---

Запрещено:

прямые вызовы моделей внутри бизнес-логики.

---

Каждый AI модуль:

имеет:

- отдельный prompt;
- структурированный JSON output;
- логирование стоимости.

---

# 9. Agent Limitations

AI-модули не создают бесконечные цепочки.

---

Максимум:

```
MAX_AI_ROUNDS = 3
```

---

Если результат неудовлетворительный:

передача человеку.

# 11. Source Collection Rules

Для Telegram источников использовать:

Telegram Client API:

- Telethon;
- Pyrogram.

---

Telegram Bot API используется только для:

- взаимодействия с пользователем;
- отправки сообщений.

---

# 12. Cost Control Rules

Каждый AI вызов сохраняет:

```
model

tokens

cost

timestamp
```

---

Система должна иметь:

дневной лимит расходов.

Пример:

```
MAX_DAILY_AI_COST = configurable
```

---

При превышении:

- уведомить владельца;
- снизить использование дорогих моделей.

# 14. Definition of MVP Success

MVP считается успешным, если система:

✅ собирает новости автоматически;

✅ анализирует минимум сотни новостей;

✅ выбирает лучшие события;

✅ отправляет подборки в Telegram;

✅ создаёт качественные черновики постов;

✅ работает стабильно каждый день;

✅ имеет контролируемую стоимость.

---

# Итог

AI Newsroom MVP — это не полноценная автономная SMM-команда.

Это первый интеллектуальный помощник редактора, который сокращает время поиска, анализа и подготовки контента.

Расширение системы происходит после подтверждения ценности MVP.
