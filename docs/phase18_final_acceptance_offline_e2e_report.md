# Phase 18 Final Acceptance — Offline End-to-End Pipeline Report

## 1. Search for a pre-existing pipeline test

`grep -rln "test_phase18_meme_pipeline\|end_to_end\|offline_pipeline\|placeholder\|meme_pipeline"
tests/` before this stage found no test exercising the full M1–M9 chain in one place — every prior

## 3. What the happy-path test exercises

`test_complete_offline_meme_pipeline_happy_path`, run against real PostgreSQL
(`phase18_validation_db`) via `tests/conftest.py`'s `db_session` fixture:

1. **NewsEvent fixture** — a real `NewsSource`+`NewsEvent` row.
2. **Meme Opportunity Assessment** — `assess_meme_opportunity()` (M1, pure function) called
   directly on the fixture event.
3. **Meme Concept** — a *real* `MemeConceptCapability.execute()` call against a `FakeLLMGateway`
   (zero network) returning fixed structured output; the real, published `prompts/meme_concept/
   v1.yaml` is loaded via `FilePromptRepository` (not a hand-rolled fixture schema — see §5 for
   why).
4. **MemeCandidate persistence** — `MemeCandidateService.create_from_concept()`.
5. **Meme Safety + Originality Assessment** — `assess_meme_safety_and_originality()` (M3, pure),
   then `attach_safety_assessment()` persists it.
6. **Meme Copywriting** — a real `MemeCopywritingCapability.execute()` call (fake Gateway, real
   published `prompts/meme_copywriting/v1.yaml`), then `attach_copy()` persists it.
7. **Meme Visual Specification / MockImageAdapter placeholder generation** —
   `generate_meme_image()` (M5) with `mode="dry_run"` against the real `MockImageAdapter` (zero
   network, zero cost), then `attach_image_result()` persists it.
8. **Deterministic renderer** — `render_meme()` (M6) on the real generated bytes, then
   `attach_render_result()` persists it.
9. **Meme Quality Gate** — `assess_meme_quality()` (M7) with every real upstream signal
   (opportunity, safety gate, render result, image result), then `apply_regeneration_bounds()`,
   then `attach_quality_assessment()` persists it.
10. **Telegram preview payload dry-run** — `send_meme_preview()` (M8) with `dry_run=True` against
    `_NeverCalledBot` (raises `AssertionError` on any attribute access — the strongest available
    proof of zero Telegram contact).
11. **Human decision persistence** — `record_editor_decision(candidate_id, "approved")`, called
    twice to prove idempotency (M9).
12. **Final candidate reload from DB** — a fresh `get_by_id()` call, asserting the fully
    accumulated state.

- **Schema versions preserved**: `final.concept_schema_version == "v1"`,
  `final.copy_schema_version == "v1"`.
- **Prompt versions preserved**: implicitly, via the real `FilePromptRepository` resolving version
  `"1"` for both capabilities (`MemeConceptCapability`/`MemeCopywritingCapability`'s own
  `PROMPT_VERSION` constants) — the capability would fail to construct its request otherwise.
- **Source evidence references remain valid**: `concept.source_fact_links` round-trips intact
  through JSON persistence and reload.
- **No network call occurs**: `FakeLLMGateway` (never a real Gateway), `MockImageAdapter` (local,
  zero-network), `_NeverCalledBot` (raises on any use) — three independent structural guarantees,
  not one.
- **No Telegram send occurs**: `preview_outcome.sent is False` asserted directly.
- **No production row is mutated**: this test only ever touches `phase18_validation_db`, inside a
  transaction `tests/conftest.py` rolls back at teardown.

  into `cumulative_cost_usd` via `add_cost()` — final value `Decimal("0.000000")`, asserted.

  randomized — inherently deterministic by construction.
- **Cost accumulates exactly once**: `add_cost()` called exactly once in the happy path; the

- **No unlimited loop**: no `while True` or retry loop of any kind appears in this test or in any

  fixed constant, not a caller-controlled loop.
- **Regeneration count remains bounded**: exercised directly in the two failure-path tests (§5).
- **Quality BLOCK cannot become READY_FOR_EDITOR**: exercised directly in
  `test_offline_pipeline_sensitive_content_never_reaches_ready_for_editor` (§5).
- **Approved candidate is not published**: `final.published is False` asserted directly — no code

  exhaustive grep).
- **Preview payload is valid**: `"AI WON'T TAKE YOUR JOB" in preview_outcome.rendered_caption`
  and `preview_outcome.has_image is True` — the caption actually rendered correctly and a real
  image was resolved.
- **Human decision is idempotent**: `record_editor_decision()` called twice, both succeed, no

## 5. Failure-path tests

Two, per the brief's own requirement (it names one; a second was added for stronger coverage):

- **`test_offline_pipeline_sensitive_content_never_reaches_ready_for_editor`**: a concept whose
  punchline references a shooting victim → M3's safety gate correctly returns `BLOCK` → M7's
  quality gate correctly returns `REJECT` (never `READY_FOR_EDITOR`) → the candidate's final
  persisted `status` is `QUALITY_REJECTED`, explicitly asserted `!= PENDING_EDITOR`.
- **`test_offline_pipeline_image_generation_failure_blocks_quality_ready`**: an image gateway that
  always raises → `generate_meme_image()` exhausts exactly `_MAX_GENERATION_ATTEMPTS` (2, asserted
  directly, never more) → `MemeImageStatus.FAILED` → M7 recommends `REGENERATE_IMAGE` → with the
  regeneration bound already exhausted (`image_regeneration_count == MAX_IMAGE_REGENERATIONS`),
  `apply_regeneration_bounds()` correctly converts this to `REJECT`, never an infinite retry —
  final persisted status `QUALITY_REJECTED`, never `PENDING_EDITOR`.

Both failure-path tests prove "state remains coherent": the candidate row is never left in an
ambiguous or partially-written state — every `attach_*` call either succeeds and advances
`status` predictably, or the candidate is simply not found (`None`), never a half-written row.

## 6. A real bug this test caught before it could ship

The test's first draft built its own hand-rolled fake `output_schema` for both new capabilities'
prompt repositories, declaring every field `{"type": "string"}` uniformly - including
`characters_objects`/`source_fact_links`/`forbidden_interpretations`, which are actually arrays.
`MemeConceptCapability`'s own floor-validation correctly rejected the resulting structured output
(`structured_output['characters_objects'] must be of type 'string', got list`). Fixed by using the
**real**, published prompt files (`FilePromptRepository`) instead of a hand-maintained
approximation — which is both the fix and a strictly better test (it now also proves the real
prompt files' own schemas are internally consistent with their capabilities' floor-validation,
not just that some schema is).
